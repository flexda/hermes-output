Hermes Agent Profile Builder
내 환경 기준 설정 가이드

대시보드에서 profile을 한 플로우로 구성할 수 있게 된 기능을, 현재 내 Hermes 운영 환경(Telegram · Native · Docker · Vercel)에 맞춰 정리한다.

출처: NousResearch X / docs.hermes-agent.nousresearch.com · 작성: oper-her 정보 가공 파이프라인 · 2026-06-11

01Profile Builder가 다루는 항목

  • Identity — name / description (이 에이전트가 누구인지)
  • Model / Provider — 메인 모델과 백업/풀링
  • Built-in skills — 기본 제공 스킬
  • Optional skills — 필요 시 설치하는 스킬 (예: info-process)
  • Skills-hub installs — 허브에서 설치한 스킬
  • MCP servers — 외부 MCP 서버 연동

원문 기준 흐름: Identity → Model → Skills → MCP 순서로 구성한다.

03설정 가이드 (내 환경 기준)

03-1Identity

  • name: Oper Hermes (현재 Telegram·Discord에서 쓰는 identity)
  • description: Ops automation + 정보 가공 파이프라인
  • 유지 원칙: 공개 게시물용 identity와 내부 ops용 identity를 분리하지 말고, 한 프로필 안에서 역할만 context로 구분한다. 이유는 profile 단위 isolation이 운영 복잡도를 올리기 때문.

03-2Model / Provider

  • 현재 OpenRouter가 인증돼 있고, model.max_tokens=8192로 세팅돼 있다.
  • Profile Builder에서 교체 가능한 부분:
    • 메인 모델을 상황별로 분리할지 여부 (예: 정책 분석용 vs 실시간 ops)
    • 현재는 default 하나로 쓰고 있으니, 나중에 profile을 나누고 싶을 때만 별도 profile 생성.
  • 지금 단계에서 우선할 것: UI에서 기존 OPENROUTER_API_KEY가 정상 노출되는지 확인.

03-3Skills

  • 현재 쓰는 스킬: info-process
  • 대시보드에서 확인할 것:
    • built-in skills에 기본 포함되는 항목
    • optional/hub installs에 info-process가 정상 노출되는지
    • skills-hub search/install 흐름이 내 현재 ~/.hermes/skills/ 구조와 호환되는지
  • 설정 팁: 스킬은 profile 단위로 관리된다. 나중에 profile을 2개(default + 공유용)로 나눌 때, skills 목록만 복붙해서 쓰면 된다.

03-4MCP servers

  • 현재 Docker Hermes에 MCP 설정이 있는지 확인해야 한다. 있다면 대시보드에서 복붙, 없다면 새로 추가.
  • MCP server를 추가할 수 있게 되면, 내 output 파이프라인(GitHub → Vercel)과 연결할 수 있는지가 우선 판단 기준이다.
  • 지금 단계에서 추천:
    • 기존 MCP 구성이 있으면 대시보드로 이전.
    • 없으면 output 파이프라인에 필요한 MCP가 있는지 확인 후 추가.

04운영 규칙으로 정리

  • Profile 단위 분리 기준: identity/model/skills 조합이 현저히 다를 때만 새 profile을 만든다. 지금은 default 하나로 유지.
  • 변경 후 검증 순서:
    1. Profile Builder에서 Save
    2. CLI에서 hermes profile list로 반영 확인
    3. Telegram에서 기본 질문 1개로 동작 확인
    4. 문제 없으면 commit
  • 보안: 이 가이드에는 .env, 토큰 값을 넣지 않는다. 대시보드에서 credential을 입력하는 부분은 별도로 관리.

05배움 포인트

Profile Builder는 Hermes를 "어떤 단위로 나눠 운영하는지" 보여준다. 내 경우:

  • profile = 역할 단위로 쓰는 게 맞는지, 아니면 profile = 환경 단위(native/docker 분리)로 써야 하는지 경험적으로 확인할 수 있다.
  • skills-hub가 정상 동작하면, 내 info-process 스킬도 hub에 publish할지 고려해볼 수 있다.
