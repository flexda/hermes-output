Getting started with loops

Claude Code 팀이 말하는 loops의 정의와, turn-based / goal-based / time-based / proactive 루프를 구성 그대로 학습할 수 있게 정리한 페이지입니다.

Executive summary

Claude Code 팀은 loops를 “stop condition이 만족될 때까지 작업 사이클을 반복하는 에이전트”로 정의합니다. 이 글은 turn-based, goal-based, time-based, proactive의 4가지 루프 유형을 구분하고, 언제 어떤 방식을 써야 하는지 설명합니다. 핵심 메시지는 처음엔 단순하게 시작하고, 검증을 시스템에 넣고, 토큰 사용량을 통제하라는 것입니다.

Key definition

“We define loops as agents repeating cycles of work until a stop condition is met.” Claude Code 팀의 핵심 정의

현장에서 “loop”는 여러 방식으로 쓰이지만, 이 글에서는 실무적으로 쓸 수 있는 정의를 채택합니다.

Main loop types

1. Turn-based

수동으로 매 턴 검증하는 루프

사용자가 각 턴을 직접 확인합니다. Claude가 컨텍스트를 읽고, 작업하고, 스스로 검토한 뒤 결과를 내놓으면 사람이 다음 턴을 이어갑니다.

2. Goal-based

/goal로 종료 조건을 거는 루프

한 번의 프롬프트로 끝나지 않을 때, “무엇을 완료로 볼지”를 정의해 두고 그 조건이 충족될 때까지 반복합니다. 명확한 성공 기준이 있을수록 잘 맞습니다.

3. Time-based

/loop와 /schedule로 주기 실행

Slack 요약, PR 점검, 리뷰 코멘트 처리처럼 외부 시스템에서 주기적으로 다시 봐야 하는 일에 적합합니다.

4. Proactive

더 긴 작업을 주도적으로 이어가는 루프

auto mode나 dynamic workflows 같은 기능과 조합해, 장기 작업에서 시스템이 더 적극적으로 다음 단계를 잡도록 합니다.

루프 유형별 핵심 차이

Loop 손에서 넘기는 것 언제 쓰는가 우선 참고할 것
Turn-based 검증 탐색, 의사결정, 처음 시도 커스텀 검증 skill
Goal-based 종료 조건 무엇이 완료인지 알 때 /goal
Time-based 트리거 정해진 주기로 다시 실행할 때 /loop, /schedule
Proactive 다음 행동의 주도권 장기 작업, 반복 조정이 필요할 때 auto mode, dynamic workflows

Goal-based 예시

/goal get the homepage Lighthouse score to 90 or above, stop after 5 tries.

Maintaining code quality

글의 핵심은 루프의 품질이 개별 결과가 아니라 루프를 둘러싼 시스템에 달려 있다는 점입니다.

  • 실패하면 단순 수정에 그치지 말고, 다음 반복에서 개선되도록 시스템에 반영합니다.
  • 검증 과정을 자동화할수록 자기 검증의 신뢰도가 높아집니다.
  • 이 방식은 루프 자체를 개선하는 접근입니다.

Managing token usage

루프는 편리하지만, 경계가 없으면 토큰이 빠르게 늘어납니다. 글은 상세 체크리스트보다는 명확한 범위와 짧은 반복의 필요성을 강조합니다.

실전 힌트: 반복 횟수, 종료 조건, 검증 방법을 처음부터 좁게 잡으면 토큰 낭비를 줄이고 루프가 길어질수록 생기는 품질 저하를 억제할 수 있습니다.

Getting started advice

Start simple

처음부터 복잡한 자동화를 만들지 말고, 가장 작은 반복부터 시작합니다.

Encode verification

사람이 매번 하던 검토를 skill이나 체크리스트로 옮겨, 에이전트가 스스로 확인하게 만듭니다.

Use loops selectively

모든 작업에 루프가 필요한 것은 아닙니다. 신뢰성, 반복성, 외부 트리거가 있는 작업에 우선 적용합니다.

Set stop conditions

무엇을 “끝”으로 볼지 숫자나 테스트 결과 같은 객관적 기준으로 정의합니다.

실전 학습 포인트

  1. 내가 반복적으로 하는 작업을 하나 고릅니다.
  2. 그 작업의 종료 조건을 한 줄로 적습니다.
  3. 검증 단계를 사람이 아닌 규칙으로 바꿀 수 있는지 봅니다.
  4. 주기 실행이 필요하면 /loop 또는 /schedule 성격으로 분리합니다.
  5. 토큰이 급격히 늘면 반복 범위를 줄입니다.
