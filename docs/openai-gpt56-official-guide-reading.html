1. 한눈에 보는 핵심

핵심 문장

마이그레이션은 모델 교체가 아니라 튜닝 패스다.

이 문장은 전체 글의 기준점입니다. 모델 이름보다 워크플로우 조정이 먼저입니다.
실무 해석

GPT-5.6은 “짧게”라는 일반론보다, 필요한 사실·제약·다음 행동을 정확히 담는 쪽이 더 중요하다고 말합니다. 즉, 덜 쓰되 덜 중요한 걸 버리라는 뜻이지, 산출물을 줄이라는 뜻은 아닙니다.

what changes

프롬프트 길이, 추론 강도, 캐싱, 모드를 함께 재검토해야 합니다.

what stays

중요한 제약, 승인 경계, 성공 기준은 여전히 명시해야 합니다.

what improves

호출 수와 중간 출력이 줄어들 수 있지만, 품질이 유지될 때만 의미가 있습니다.

2. 마이그레이션은 튜닝 패스

migration rule

슬러그 교체로 끝내지 않는다

이 가이드는 모델 이름만 바꾸는 식의 마이그레이션을 권하지 않습니다. 대표 작업 기준으로 추론 설정을 비교하고, 기존 프롬프트를 그대로 복사하지 말고 재조정해야 한다고 말합니다.

practical note

대표 워크로드로 검증한다

품질이 중요한 작업이라면 한 단계 낮은 추론 설정까지 같이 비교해보는 쪽이 좋습니다. 비용과 지연시간만 줄이고 품질을 잃는 이동은 성공이 아닙니다.

항목 무엇을 확인하나 왜 중요한가
모델 선택 sol / terra / luna 중 어떤 조합이 맞는지 성능·비용·빈도 균형이 다릅니다.
추론 강도 xhigh, max, pro 모드 비교 더 깊게 생각할지, 더 빨리 답할지 결정합니다.
프롬프트 길고 일반적인 지시를 줄였는지 불필요한 반복이 줄고 필요한 행동이 선명해집니다.

3. Sol / Terra / Luna

sol

플래그십 성능

가장 높은 품질이 필요한 복잡한 작업에 둡니다.

terra

지능과 비용의 균형

실무에서 가장 넓게 쓸 수 있는 중간 지점입니다.

luna

효율 중심

대용량·고빈도 워크로드를 가볍게 처리할 때 맞습니다.

권장 해석

이 셋은 “무조건 상위 모델”이 아니라 “작업 유형에 맞는 도구 선택”으로 읽는 편이 맞습니다.

4. 프롬프트는 더 짧게, 하지만 더 정확하게

짧게 유지하라

“간결하게 답하라”, “짧게 유지하라” 같은 일반론은 오히려 필요한 산출물을 줄일 수 있습니다.

즉, 단순 축약이 아니라 정보 밀도를 조절해야 합니다.
결론부터 말하라

결론을 먼저 내고, 그 결론을 지지하는 증거와 중요한 caveat, 다음 행동을 붙입니다.

불필요한 소개와 반복은 잘라내되, 근거는 남겨야 합니다.
copyable snippet

응답 스타일 지시

Lead with the conclusion. Include the evidence needed to support it, any material caveat, and the next action. Omit secondary detail and repetition.
copyable snippet

불필요한 장식 제거

Be direct and tactful. Acknowledge friction specifically when relevant. Avoid canned reassurance and unnecessary sign-offs.

5. 새 기능과 활용 포인트

ptc

Programmatic Tool Calling

모델이 JS 코드로 여러 도구를 엮어 중간 결과를 처리하는 방식입니다.

multi-agent

서브에이전트 병렬화

독립 작업을 나누면 시간 단축과 성능 향상에 도움이 됩니다.

prompt caching

명시적 프롬프트 캐싱

재사용 prefix를 직접 지정해 비용과 속도를 조정할 수 있습니다.

persisted reasoning

추론 유지

이전 턴의 추론 항목을 다음 턴에서 재사용해 멀티턴 효율을 높입니다.

max / pro

더 깊은 추론

max와 pro는 품질이 더 중요할 때 쓰는 선택지로 읽으면 됩니다.

intent

의도 이해

모든 단계를 다 적지 않아도 되지만 중요한 제약은 여전히 써야 합니다.

copyable snippet

작업 지시 방식

For requests to answer, explain, review, diagnose, or plan, inspect the relevant materials and report the result. Do not implement changes unless the request also asks for them.
For requests to change, build, or fix, make the requested in-scope local changes and run relevant non-destructive validation without asking first.
copyable snippet

프로 모드 선택 기준

Use Pro mode when quality matters more than latency or token cost.
Use lower effort or shorter paths when the task is simple and the baseline quality is already good.

6. 작업 기준으로 프롬프트하기

1. 작업 정의 모드가 아니라 무엇을 하게 할지를 먼저 적습니다.
2. 필요한 재료만 제공 결론, 증거, 제약, 다음 행동에 필요한 정보만 남깁니다.
3. 결과 검증 호출 수가 줄었는지보다 품질이 유지되는지 먼저 봅니다.
4. 재조정 품질이 안 맞으면 prompt / reasoning / cache / mode를 다시 튜닝합니다.
원문에서 강조한 실무 포인트
  • 호출, 턴, 중간 출력이 줄어드는 것은 품질이 유지될 때만 의미가 있습니다.
  • 모드명을 외우는 것보다 작업의 구조를 적는 것이 더 중요합니다.
  • 중요한 제약 조건, 승인 경계, 성공 기준은 생략하지 않아야 합니다.

7. 바로 적용할 체크리스트

migration

마이그레이션 확인

  • 대표 작업 3개를 고른다
  • 이전 모델과 GPT-5.6을 비교한다
  • 프롬프트 길이와 추론 강도를 함께 조정한다
prompt

프롬프트 정리

  • 결론을 먼저 쓰게 한다
  • 중복 안내를 제거한다
  • 필요한 caveat와 다음 행동을 남긴다
mode

모드 선택

  • 복잡한 작업은 pro 또는 높은 추론
  • 대량 작업은 효율 중심
  • 응답 품질이 기준이다
safety

검증 기준

  • 평가 없이 모드만 바꾸지 않는다
  • 중요 제약은 명시한다
  • 작업별로 결과 품질을 확인한다
Done when

대표 작업에서 이전 모델과 GPT-5.6을 비교했고, 프롬프트·추론 강도·캐싱·모드에 대한 재조정이 문서로 남아 있으면 적용 단계가 끝납니다.
