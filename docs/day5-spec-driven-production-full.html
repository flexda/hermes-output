1. Introduction

What changed

개발은 더 이상 API 문서를 뒤적이며 수동으로 코드를 맞추는 일이 아닙니다. AI 코딩 에이전트가 검색, 실행, 테스트, 커밋까지 묶어 처리합니다.

그러나 속도는 해결책이 아니라, 새로운 병목을 드러내는 신호입니다.
핵심 전환

사람의 시간은 구현에서 설계·검토·통합으로 옮겨갑니다. 코드는 재생성 가능하지만, 품질 기준과 협업 구조는 재생성되지 않습니다.

그래서 이 백서는 “코드를 더 많이 쓰는 법”이 아니라 “시스템을 더 잘 다루는 법”을 다룹니다.

Illusion of speed버그·검토·통합이 같이 커짐
Downstream shift병목이 사람 쪽으로 이동
New disciplinespec, eval, policy, sandbox

2. Spec-Driven Development (SDD)

code-first → spec-first

코드는 이제 소모품이다

좋은 명세가 있으면 코드베이스는 다시 생성할 수 있습니다. 핵심은 구현을 먼저 손대는 것이 아니라, AI가 따라야 할 설계도를 먼저 만드는 일입니다.

이 관점에서 개발자는 타이핑하는 사람보다 기술 아키텍트에 가깝습니다.

Architectural North Star

명세는 방향을 잃지 않게 만든다

context fragmentation을 막는 가장 강한 장치가 명세입니다. 문서가 source of truth가 되면 인간과 에이전트가 같은 기준을 봅니다.

specs/ 폴더는 단순한 문서 저장소가 아니라, AI가 읽고 검증하는 작업 표면입니다.

What belongs in a spec
  • 전체 기술 설계
  • DB schema / API contract
  • 도구와 라이브러리 버전
  • 왜 이걸 만드는지에 대한 배경
Format
  • Markdown은 narrative instructions에 좋다
  • YAML은 구조화된 설정과 schema에 좋다
  • 중요한 건 사람이 읽을 수 있어야 한다는 점
BDD
  • Scenario / Given / When / Then
  • State → Action → Outcome
  • 사용자 행동을 기준으로 검증

3. A good specification / Which format to use? / Behavior Driven

Layer What it does Why it matters
Spec Defines architecture, contracts, scenarios, and constraints Lets the agent regenerate code without guessing
Markdown Narrative instructions and human-readable context Anchors attention and keeps the story legible
YAML Structured settings, deep configuration, nested data Reduces format tax for machine parsing
Gherkin Scenario / Given / When / Then behavior specs Forces the model to think in outcomes, not vibes
Behavior Driven

BDD turns ambiguous ideas into explicit architecture. It is not just a testing style; it is a way to define what good looks like before code exists.

Principle

Don’t say “make a login page.” Break down requirements, database schemas, API contracts, diagrams, tools, version numbers, background context, and edge cases.

4. Where do the instructions live?

Chat interface

Short-lived, session-specific

Use the chat for orchestration and immediate feedback, not for dumping a giant design document.

Long prompts blow context budget, increase latency, and fracture the thread.

specs/ folder

Versioned source of truth

Technical design, BDD scenarios, API contracts, and schemas live here. The agent can index and verify them directly.

This is the place where the blueprint survives beyond a single chat session.

Agent Skills

Reusable workflows for feature-specific behavior.

System prompts

Global identity and project-specific rules layered hierarchically.

Project spec

The project’s DNA, read by the CLI agent and prioritized locally.

5. Different Prompts for Different Use Cases

Architect

Project generation

Start with scaffolding, structure, and constraints. No YOLO mode.

Builder

Feature generation

Keep style aligned with the existing codebase and request a diff-aware build.

Forensic

Bug fixing

Use logs, reproduction commands, and failing tests before asking for a patch.

Documentation writing

Docs are source of truth. Keep README.md, CHANGELOG.md, and docstrings synchronized.

Data engineering

Always surface the exact SQL or command used to produce results.

6. MCP: One Integration, Every Framework

The idea

USB-C for AI tools

Build one MCP server for a database, API, or file system, and any compatible agent can use it. The integration layer becomes reusable instead of being rewritten per client.

That separation is what turns a narrow feature demo into a stable platform boundary.

Server / client

Expose tools, then discover them

The server publishes tools; the client initializes a session, lists tools, and calls them.

The paper shows a SQLite-backed example in roughly forty lines.

copyable snippet

MCP server

import sqlite3
from mcp.server import Server
from mcp.server.stdio import stdio_server
from mcp.types import Tool, TextContent

server = Server("knowledge-base")
db = sqlite3.connect("knowledge.db")

MCP client

from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

server_params = StdioServerParameters(command="python", args=["mcp_server.py"])
async with stdio_client(server_params) as (read, write):
    async with ClientSession(read, write) as session:
        await session.initialize()

7. Team Culture & Process Evolution

What breaks
  • Huge PRs
  • Merge conflicts in shared files
  • Context fragmentation across timezones
What changes
  • Summaries and risk snapshots before review
  • Smaller integration chunks
  • Human attention moves to architecture
What scales
  • Managed reviewer
  • Hybrid runtime
  • Custom runtime that understands the whole system
Sustainability

Approval fatigue is real. Frequent AI users can end up clicking approve reflexively. The paper pushes back with quiet hours and weekly insight sessions so learning becomes shared instead of isolated.

8. Code Reviews / Sustainability

Review at speed

Review work shifts from syntax policing to integration risk, side effects, and architectural impact. Bundled summaries help humans focus on what changed and what could break.

Operational boundary

Large-scale AI adoption needs a process that handles conflict, fatigue, and async reviews. The team workflow is part of the product surface now.

9. Zero-Trust Development: Building the Safety Net

Guardrails

Structural + semantic gating

Rules at the tool and environment layer, plus intent checks on top.

Sandbox

Restricted execution

Ephemeral low-privilege containers reduce blast radius.

HITL

Human sign-off

High-stakes actions still need a human in the loop.

copyable snippet

policy_server.py

class PolicyService:
    def is_tool_allowed(self, tool_name: str) -> bool:
        env_config = self.config.get("environments", {}).get(self.env, {})
        if tool_name in env_config.get("blocked_tools", []):
            return False
        role_allows = self.config.get("roles", {}).get(self.role, {}).get("allowed_tools", [])
        return "*" in role_allows or tool_name in role_allows
AI-generated tests

Ask the agent to generate failing tests or reproduction commands before the fix.

Evaluation

Binary tests are not enough for ML-driven behavior; score-based evaluation catches drift.

Context hygiene

Sanitize prompts and inputs so context hallucination does not leak secrets or stale values.

10. Summary

Conclusion

What the paper is really saying

AI has moved the bottleneck away from code production and toward orchestration, review, testing, integration, and deployment. The solution is not just better prompts; it is a system of specs, tools, policy, and team discipline.

Where to start
  1. Write the spec first.
  2. Choose Markdown for narrative, YAML for structure.
  3. Separate prompt types by workflow.
  4. Add sandboxing, review gates, and evaluation.
