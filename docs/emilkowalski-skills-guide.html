1. 저장소 한눈에 보기

emilkowalski/skills는 디자인 엔지니어 Emil Kowalski가 만든 AI 에이전트용 스킬 모음입니다. 핵심 목적은 인터페이스의 미세한 품질, 특히 애니메이션과 모션 판단을 더 정확하게 만드는 것입니다.

Design engineers UI polish Animation craft Agent Skills Prompt reuse
이 저장소가 해결하는 문제

에이전트가 “작동은 하지만 덜 멋진” UI를 만드는 이유는 의도, 이징, 물성, 회복성, 빈도 같은 디테일을 자주 놓치기 때문입니다. 이 스킬들은 그 빈틈을 메우는 체크리스트 역할을 합니다.

3. 스킬별 설명

main skill emil-design-eng

저장소의 중심 스킬입니다. Emil Kowalski의 디자인 엔지니어링 철학을 담고 있으며, 애니메이션뿐 아니라 버튼 상태, 깊이감, spacing, 레이아웃 감각 같은 UI 전반의 품질을 다룹니다.

  • UI를 “그냥 돌아가는 수준”에서 “손맛이 있는 수준”으로 올리고 싶을 때
  • 컴포넌트/화면 리뷰에서 폴리시 관점이 필요할 때
  • 에이전트가 디자인 결정을 더 잘 하게 만들고 싶을 때

review review-animations

애니메이션과 모션 코드를 “리뷰”하는 전용 스킬입니다. 한 diff에 대해 얼마나 정교하게 동작하는지 점검할 때 쓰는 편이 맞습니다.

  • 이징이 너무 둔한지
  • 상호작용 빈도에 비해 과한 모션이 들어갔는지
  • 입출력/인터랙션에 맞게 잘 설계됐는지

audit improve-animations

코드베이스 전체를 훑어 애니메이션 문제를 우선순위로 정리하고, 실행 가능한 수정 계획을 쓰는 스킬입니다. source code를 직접 고치지 않고, 다른 에이전트가 수행할 수 있는 계획서만 만듭니다.

  • 한 화면이 아니라 전체 앱의 모션 품질을 점검하고 싶을 때
  • 고급 모델로 진단, 저렴한 모델로 실행하는 분업이 필요할 때
  • 수정 범위를 계획서로 분리하고 싶을 때

glossary animation-vocabulary

사용자가 막연하게 묘사한 모션을 정확한 용어로 되돌려주는 역조회 사전입니다. “그 팝업이 툭 튀어나오는 느낌” 같은 설명을 정리할 때 특히 유용합니다.

  • 효과 이름이 기억나지 않을 때
  • AI에게 정확한 용어로 요구사항을 다시 쓰고 싶을 때
  • 비슷한 모션 용어를 구분해야 할 때

motion philosophy apple-design

Apple의 WWDC 디자인 토크를 바탕으로, fluid motion, spring, gesture, momentum, translucency, reduced motion 같은 개념을 웹 구현 관점으로 옮겨 놓은 스킬입니다.

  • 드래그, 스와이프, 시트, 카드 전환처럼 손맛이 중요한 UI
  • 사용자 입력에 즉시 반응하는 인터랙션
  • “Apple처럼 자연스러운 느낌”을 목표로 하는 경우

4. 활용 예시

예시 1 · emil-design-eng

UI 리뷰를 맡기고 싶을 때

이 화면의 버튼, 카드, 진입 애니메이션을 Emil Kowalski 관점에서 리뷰해줘.
특히 다음을 봐줘:
- 버튼 press feedback이 자연스러운지
- shadow와 border가 너무 무겁지 않은지
- scale / opacity / easing이 상호작용 빈도에 맞는지

문제점이 있으면 왜 문제인지, 어떤 방식으로 수정할지 짚어줘.
예시 2 · review-animations

애니메이션 diff 리뷰를 맡기고 싶을 때

아래 diff의 애니메이션만 리뷰해줘.
- enter / exit timing
- easing curve 선택
- keyframe의 시작/종료 상태
- 성능 상 GPU 친화적인지

애매하면 승인보다 지적 위주로, 수정 우선순위도 같이 줘.
예시 3 · improve-animations

코드베이스 전체 점검과 개선 계획이 필요할 때

이 저장소의 애니메이션을 전체적으로 점검해서,
1) 가장 큰 문제 5개를 우선순위로 정리하고
2) 각 항목을 다른 에이전트가 실행할 수 있게
   파일 경로, 수정 포인트, 기대 효과가 포함된 계획으로 작성해줘.

직접 수정하지 말고 계획만 써줘.
예시 4 · animation-vocabulary

효과 이름이 생각 안 날 때

"버튼이 살짝 튀어 오르면서 나타나는 그 느낌"을
디자인/모션 용어로 뭐라고 부르는지 알려줘.
가능하면 가장 가까운 용어를 우선 제시하고,
비슷한 대안이 있으면 차이도 짚어줘.
예시 5 · apple-design

Apple 스타일의 자연스러운 인터랙션을 만들고 싶을 때

드래그 가능한 bottom sheet를 Apple 스타일에 가깝게 설계하고 싶어.
- pointer-down에서 즉시 반응
- velocity를 살린 스프링 전환
- 중간에 방향 전환 가능
- reduced motion 대응

웹 구현 기준으로 설계 원칙과 코드 힌트를 정리해줘.

5. 추천 사용 흐름

스킬 선택

먼저 문제를 분류합니다. 용어가 필요한지, 단일 diff를 리뷰할지, 전체 코드베이스를 진단할지, 아니면 Apple식 motion principle이 필요한지부터 고릅니다.

목표를 좁게 말하기

“좋게 해줘”보다 “입장 애니메이션의 easing과 duration을 봐줘”처럼 범위를 작게 써야 스킬이 더 잘 작동합니다.

출력 형식 기대치 정하기

리뷰용인지, 계획서인지, 용어 사전인지 미리 말하면 결과가 훨씬 안정적입니다. 특히 improve-animations는 계획서 형식이 맞습니다.

결과를 적용

추천받은 용어, 원칙, 계획을 실제 코드나 프롬프트에 반영합니다. 이 저장소의 강점은 “예쁜 설명”이 아니라 “바로 실행 가능한 절차”입니다.

6. 설치 방법

README에 적힌 표준 설치 명령은 아래와 같습니다. 

npx skills@latest add emilkowalski/skills

설치 후에는 에이전트가 해당 스킬의 SKILL.md를 읽고, 그 안의 절차와 가드레일을 따라 작업하게 됩니다.

7. 자주 묻는 점

이 저장소는 코드 라이브러리인가요?

아니요. 실행 코드보다 에이전트가 읽는 지침 파일에 가깝습니다. 프론트엔드 구현보다 판단의 질을 높이는 쪽에 목적이 있습니다.

어떤 작업에 가장 잘 맞나요?

UI polish, motion design, gesture-driven 인터랙션, 애니메이션 감사, 용어 정리처럼 “감각과 규칙이 동시에 필요한 작업”에 잘 맞습니다.

일반적인 코드 작업에도 유용한가요?

일부는 유용하지만, 이 저장소의 핵심 강점은 분명히 디자인/모션/인터랙션에 있습니다.

이 페이지를 한 줄로 요약하면?

“에이전트가 애니메이션과 UI를 더 맛있게 만들게 돕는 작은 전문 지식 묶음”입니다.
